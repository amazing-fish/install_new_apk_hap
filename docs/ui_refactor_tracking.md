本仓库当前没有可用的 GitHub CLI，本次先用仓库内文档跟踪三阶段治理。后续如需迁移到 GitHub issue，可按下面三个阶段直接拆为 issue，并把验收标准复制过去。

## 当前进展（2026-06-03）
- 阶段一已完成：设备表格列顺序、设备摘要、选中设备摘要、安装包摘要均已接入，并由单元测试覆盖关键格式化逻辑。
- 阶段二已完成主体拆分：已将外显格式化逻辑拆到 `src/ui_display.py`，将颜色常量与 ttk style 配置拆到 `src/ui_styles.py`，将主界面布局构建拆到 `src/ui_layout.py`。
- 下一步：进入阶段三前，建议先补一次人工界面走查，重点看最小窗口、常用桌面尺寸、长设备码和长包名。

## 阶段一：状态接入与显示一致性
目标：修复当前外显改造中已经引入但未完整接入的状态展示问题，确保界面看到的内容与内部选择一致。

验收标准：
- [x] 设备表格列顺序正确：名称、平台、状态、设备码。
- [x] 设备刷新后，设备统计摘要同步更新。
- [x] 设备选择变化后，执行区与状态栏的已选设备摘要同步更新。
- [x] APK/HAP 扫描和下拉切换后，安装包摘要同步更新。
- [x] 关键格式化逻辑有单元测试覆盖。

## 阶段二：UI 结构拆分
目标：把 `src/main.py` 中的视觉样式、布局构建和业务编排拆出边界，降低后续外观迭代成本。

验收标准：
- [x] 样式常量和 ttk style 配置从 `App` 主类中拆出。
- [x] 设备区、安装包区、执行区、日志区形成清晰的构建边界。
- [x] `App` 保留应用状态编排和后台线程回写，不再承载大段重复布局代码。
- [x] 拆分后现有测试全部通过，交互行为不漂移。

## 阶段三：体验重排与视觉完善
目标：在结构稳定后做真正的外显升级，而不是继续在单文件里叠样式。

验收标准：
- 主工作流按“设备 -> 安装包 -> 执行 -> 日志”清晰组织。
- 高风险动作、耗时动作、只支持特定平台的动作有明确状态反馈。
- 窗口在最小尺寸和常用桌面尺寸下内容不重叠、不截断。
- 日志、状态栏和弹窗文案语义一致。
