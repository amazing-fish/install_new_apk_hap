第一阶段只迁移显示格式化并接入摘要；保持安装命令、配置 schema、发布版本、刷新联动、全量候选、安装快照及日志时序。执行区和状态栏共享一个当前选择摘要；包摘要显示当前选择，已开始安装的参数仍以点击快照与请求日志为准。

## 第三阶段验证与版本

- 原界面在 480x560、20 台长设备码全选时，底栏摘要挤占高度，刷新、安装与日志控件不再映射可见；该场景已作为本轮回归输入。
- 初始宽度贴合四列基准宽度（当前约 590x740），最小 480x560；设备区至少 4 行、最多 8 行。设备/包/日志使用紧凑原生布局，名称/目录操作同行，按钮按各自宽度依次换行，不共享跨行网格列宽；设备动作说明行已移除。固定底部执行入口，仅在底栏/下拉框显示不全时展开完整摘要，保留长内容滚动和键盘访问。
- 真实 Tk 测试覆盖 480x560 / 当前默认尺寸 / 1024x800 与 Tk scaling 1.0 / 1.5 / 2.0 的组合、20 台长名称设备、长包名、多候选、Tab 与页面快捷键、嵌套滚轮、平台与忙碌切换，以及失败/异常/中止/跳过目标的不同终态。另验证默认窗口同屏、完整摘要展开/收起、连续缩窄与放宽时的按钮位置及忙碌文案变长；缩放用例结束时恢复原始 Tk display scale。
- 相同设备和安装包刷新结果不再重复刷日志，文件大小/修改时间/候选或设备状态变化仍记录；错误、恢复、清空日志后的首条结果、安装前校验和安装日志均有聚焦回归。
- 已保留刷新排序、选择恢复、安装点击快照、配置与日志时序回归；Windows 样例截图用于界面走查。Tk scaling 参数测试不等同于所有系统 DPI 或多显示器组合的人工验收。
