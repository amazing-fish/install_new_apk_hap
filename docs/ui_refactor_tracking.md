## 当前瓶颈

1. **计划与交付状态脱节。** #32/#33 原文声称“本地已完成”，但主线没有摘要模块；完整跟踪文档此前只在 #35 分支。旧 PR 同时混合状态、结构、视觉、命令寻址，无法作为一个已验收阶段整体落地。
2. **显示缺少共同更新入口。** 主线在刷新、命名、包切换时分别维护控件；缺少设备/选择/包摘要。第一阶段建立纯格式化与事件同步，复用现有身份和安装快照，后续布局可以消费这些状态。
3. **结构边界仍待拆分。** 调查基线的 `main.py` 为 962 行，布局构建和状态编排位于同一类；这提高 UI 改动触及安装链路的机会。具体拆分留给 #33，不以行数本身作为删除依据。
4. **主线缺少 PR 自动验证。** 原流程仅手动/tag 打包时跑测试。本阶段补 PR Windows 测试，避免继续依赖旧 PR 的少量测试结果。
5. **独立功能混入 UI。** #35 的 HDC 检测 fallback 未传递到安装/日志命令，已有 [P2 review](https://github.com/amazing-fish/install_new_apk_hap/pull/35#discussion_r3350656341)。主线仍统一依赖 PATH，这个缺口属于旧实现而非已发布 fallback 的回归。

包扫描在主线程中按修改时间排序；大目录可能影响响应，但本次没有性能测量数据，不能把它认定为当前主要耗时根因。真实安装耗时已有 #46 的阶段日志可供后续测量。
